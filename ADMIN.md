## 1) Що вміє адмінка

- Перегляд усіх товарів (звичайні + custom)
- Створення товару
- Редагування товару
- Видалення товару
- Завантаження фото на Cloudinary
- Керування купонами
- Керування акціями (вкладка **🔥 Акції**)
- Перегляд користувачів бота з лічильниками запусків (вкладка **👥 Користувачі**)
- **✨ Пропозиції ШІ**: кнопка «Знайти нові» — Claude шукає популярні моделі (MakerWorld, Printables, Thingiverse)
  і пише картки товарів у стилі каталогу (назва, опис, ціна, категорія) з посиланням на модель і поясненням ліцензії.
  «Відкрити й додати» відкриває звичайну форму товару з заповненими полями; після збереження пропозиція переходить у «Додані».
  Потрібен `ANTHROPIC_API_KEY` (окрема оплата Claude API); модель — `AI_SUGGESTIONS_MODEL`, за замовчуванням `claude-opus-5-5`.

### Пропозиції ШІ без API: browser-harness

Поки на сервері немає оплаченого `ANTHROPIC_API_KEY`, пропозиції й фото додає **агент Claude Code через браузер**, а не
кнопка «Знайти нові». Метод: [browser-use/browser-harness](https://github.com/browser-use/browser-harness) — агент керує
твоєю справжньою Chrome (CDP), уже залогіненою, і працює через адмінку як звичайний адмін.

- **Встановлення:** `uv tool install --python 3.12 --upgrade --force browser-harness` (версія 0.1.13), команда `browser-harness`.
- **Підключення:** в Chrome відкрий `chrome://inspect/#remote-debugging` і постав галочку «Allow remote debugging for this browser instance».
  Без цього `browser-harness --doctor` показує `daemon alive — FAIL`.
- **Що агент бачить:** весь браузер із відкритими вкладками й сесіями. Тому працює тільки з явного дозволу власника
  і лише в межах завдання (адмінка, сторінки моделей). Чужі акаунти й паролі не чіпає, форми з платежами не заповнює.
- **Записи екрана:** вимкнені за замовчуванням (`browser-harness recordings` → `off`). Не вмикати без потреби.
- **Телеметрія** harness: ввімкнена за замовчуванням; вимкнути — `browser-harness telemetry disable`.

Сценарій, який агент виконує:
1. Відкрити «Пропозиції ШІ» в адмінці, вкладка «Нові».
2. Для кожної пропозиції з менш ніж 10 фото — зібрати фото зі сторінки моделі (галерея, відгуки, «Prints/Makes»),
   тільки прямі https-посилання на зображення, без логотипів і дублікатів. Додати через «Ще фото» або вручну в редакторі.
3. Додати 10 нових пропозицій (з позиціями/розмірами, якщо є) через `POST /api/admin/ai-suggestions/manual`
   з сторінки адмінки (той самий авторизований запит, що й решта кнопок). Вони потрапляють у «Нові», у каталог нічого не додається.
4. Звітувати власнику: що додано, які фото лишились, чого не вдалось.

Коли з'явиться ключ API, кнопки «Знайти нові» й «Доповнити фото» працюють як і раніше; цей метод — запасний.

### Пропозиції ШІ: налаштування

Код — `services/ai_suggestions.py`, промпти й чорний список змінюються там.

**Фото (до 10 на пропозицію).** При пошуку ШІ збирає якомога більше різних фото: галерея моделі, а також фото з відгуків
і розділів «Prints / Makes / Made it» (реальні відбитки часто кращі за рендери). Ліміт — `IMAGES_MAX = 10`. Усі посилання
перевіряються сервером (`verify_images`): мертві й не-зображення відкидаються (403/429 — захист від хотлінку — лишаємо).
У картці пропозиції видно всі фото з лічильником «N з 10»; клік — перегляд, у формі товару «+ Додати» завантажує
вибране фото в Cloudinary. Кнопка **🖼 Ще фото** на картці (або **🖼 Доповнити фото** у шапці — для всіх нових, де фото менше 10)
запускає окремий фоновий пошук додаткових фото вже знайденої моделі; нові фото додаються до наявних без дублікатів.

**Позиції (варіанти) товару.** Якщо в моделі кілька розмірів, ШІ повертає `variants` — 2–10 позицій із підписом
(«10 см», «15 см», «З кільцем») і ціною кожної. Ціна товару = найнижча ціна позицій, подарунок для таких товарів вимкнено
(як у звичайних товарів з варіантами). Якщо придатних позицій менше двох — товар лишається зі звичайною ціною.
У картці пропозиції позиції видно чіпами, а «Відкрити й додати» одразу заповнює редактор варіантів у формі товару.

**Звідки фото.** Беремо лише галерею моделі й фото з відгуків та розділу «Prints / Makes». **З опису (Description) фото не беремо:**
там часто реклама інших товарів автора, яка не має відношення до цієї моделі. Це правило є і в промпті ШІ, і в ручному збиранні.

**Рейтинг, скачування, лайки й друки.** У картці пропозиції є чіпи «★ рейтинг · ⬇ скачування · ♥ лайки · 🖨 друки» зі сторінки моделі
(поле `source_stats` / `sourceStats`). Джерело (MakerWorld, Printables тощо) видно чіпом з назвою сайту. Ліцензія пишеться в полі «Ліцензія»,
а перевіряє її власник; агент лише вказує текст зі сторінки.

**Чорний список тем.** ШІ не пропонує демонічне, окультне й магічне (демони, дияволи, чаклуни, відьми, ритуали, таро),
Гелловін і похмуре (черепи, скелети, вампіри, зомбі, привиди, кров, жахи), брудне й для дорослих (NSFW, еротика, грубі жарти).
Працює двічі: у промпті (ШІ не обирає такі моделі) і в коді — `BLOCKED_STEMS`: якщо корінь зі списку
трапляється на початку слова в назві, описі, примітці, матеріалі чи назві моделі, пропозиція відкидається. Старі нові пропозиції з такими темами
при наступному пошуку (товарів чи фото) автоматично переходять у «Відхилені». Для нових тем
додай корінь у `BLOCKED_STEMS`. Побічний ефект: «магічний кубик» чи «Wizard» також відсіється — це свідомо.

UI-файл: `admin-panel.html`  
Backend-обробники: у `bot.py`

> Нова адмінка (бічне меню, Огляд, Черга друку, Клієнти, Розсилки, форми-шухляди з превʼю) описана
> в [REDESIGN.md](REDESIGN.md#4-адмінка--сторінки) — етапи 4–5.
>
> Тимчасово (етап 2) у поточній формі товару: **опис**, **примітка**, **відео** (посилання або завантаження mp4/mov до 25 МБ),
> для індивідуальних — налаштування поля персоналізації (ліміт символів, підказка, приклад, великі літери).
> На вкладці «🔥 Акції» — поріг показу «N продано» в картці товару.

## 2) Критично важливі ENV змінні

```env
BOT_TOKEN=...
OWNER_ID=718746623
ORDERS_CHAT_ID=-1003739884073
ADMIN_WEBAPP_URL=http://localhost:8080/admin/panel
VALIDATE_INIT_DATA=false
PORT=8080

CLOUDINARY_CLOUD_NAME=...
CLOUDINARY_API_KEY=...
CLOUDINARY_API_SECRET=...
```

### Ролі змінних

- `OWNER_ID` — **адмін-користувач** (особистий Telegram ID, позитивний).
- `ORDERS_CHAT_ID` — **чат/канал для замовлень** (`-100...` для каналів).
- `SUBSCRIPTION_CHANNEL` *(необов'язково)* — **канал за замовчуванням** для промокодів з галочкою
  **«📢 Лише для підписників каналу»**. `@username` або числовий `-100...`.
  На кожному купоні можна задати свій канал/групу в полі під галочкою — тоді ENV не використовується.
  Бот має бути учасником/адміністратором кожного такого каналу, інакше перевірка підписки не спрацює
  (і код вважатиметься недоступним для всіх).
- `SUBSCRIPTION_CHANNEL_URL` *(необов'язково)* — посилання на канал для тексту користувачу
  («Підпишись: …»). Якщо не задано й `SUBSCRIPTION_CHANNEL` — це `@username`, посилання
  будується автоматично (`https://t.me/username`).

> Важливо: не використовувати `OWNER_ID` як канал. Це ламає логіку прав для `/admin`.

## 6) API адмінки

- `GET /admin/panel`
- `GET /api/products`
- `GET /api/products/{id}`
- `POST /api/products`
- `PUT /api/products/{id}`
- `DELETE /api/products/{id}`
- `POST /api/upload-photo` (multipart, поле `file`)
- `GET /api/promotions` — активні акції для вітрини (публічний)
- `GET /api/admin/promotions` — усі акції (адмін)
- `POST /api/admin/promotions` — створити акцію
- `PUT /api/admin/promotions/{id}` — оновити акцію або перемкнути `{"active": true|false}`
- `DELETE /api/admin/promotions/{id}` — видалити акцію
- `GET /api/admin/users` — список користувачів бота
- `GET /api/admin/ai-suggestions` — пропозиції ШІ і стан пошуку
- `POST /api/admin/ai-suggestions/generate` — запустити пошук `{"count": 1..10, "focus": "…"}` (у фоні)
- `POST /api/admin/ai-suggestions/photos` — знайти ще фото `{"ids": [..]}` (без `ids` — для всіх нових, де фото менше 10; у фоні)
- `POST /api/admin/ai-suggestions/manual` — додати пропозицію вручну (JSON як у пропозицій ШІ: name, price, cat, image_urls, variants…); ті самі правила: чорний список, дублікати, перевірка фото
- `PUT /api/admin/ai-suggestions/{id}` — статус `new` / `rejected` / `published` (+ `productId`)
- `DELETE /api/admin/ai-suggestions/{id}` — видалити пропозицію

## 9) Типові проблеми

### `/admin` не працює
- Перевірити `OWNER_ID` (має бути ваш user id)
- Перезапустити бота після зміни `.env`

### Замовлення не приходять у канал
- Перевірити `ORDERS_CHAT_ID`
- Переконатися, що бот доданий у канал і має право публікації

### Фото не завантажуються
- Перевірити `CLOUDINARY_*`
- Переконатися, що файл — зображення і <= 25MB

## 11) Акції

Вкладка **🔥 Акції** в адмін-панелі. Кожну акцію можна миттєво увімкнути/вимкнути перемикачем —
зміна одразу діє і на сторінці «Акції» у застосунку, і при розрахунку суми замовлення на сервері.

### Типи акцій

| Тип | Що робить | Ключові поля |
|---|---|---|
| `order_percent` | % знижки на всю суму | `value` (%), `min_order` |
| `order_fixed` | знижка в ₴ на всю суму | `value` (₴), `min_order` |
| `gift_threshold` | безкоштовний подарунок за N товарів | `category`, `min_items`, `max_gift_price` |
| `info` | банер без автоматичної знижки | тільки текст/emoji/бейдж |

### Правила розрахунку

- Якщо активних знижкових акцій кілька — застосовується **найвигідніша для клієнта**.
- За замовчуванням купон **скасовує** автоматичну акційну знижку.
- Знижки **сумуються** лише коли виконано дві умови: увімкнено глобальний перемикач
  **«🔥 + 🏷️ Дозволити сумування купонів з акціями»** (вкладка «Акції») **і** на самому купоні
  стоїть галочка **«Сумувати з акційною знижкою»**. Тоді обидві знижки рахуються від суми
  кошика й додаються; підсумок округлюється один раз (залишок від округлення знімається з акції,
  щоб купон показував свій номінал). У кошику клієнт бачить два окремі рядки — акцію та промокод.
- Промокод із галочкою **«📢 Лише для підписників каналу»** показується у `/mycoupons`
  і застосовується на касі лише підписникам каналу/групи (перевірка через `getChatMember`, кеш 60 с).
  Канал береться з поля на купоні, а якщо воно порожнє — з `SUBSCRIPTION_CHANNEL` (ENV).
  Якщо не задано ні там, ні там — галочка нічого не обмежує.
- `starts_at` / `ends_at` — необов'язкові дати; поза вікном акція не діє, навіть якщо увімкнена.
- `PROMOTION_ENABLED=false` в ENV — глобальний вимикач усіх акцій.
- Джерело істини — сервер: фронтенд лише малює правила з `GET /api/promotions`.

### Подарунок

Подарунком може стати товар із галочкою **«🎁 Може бути подарунком»** і ціною не вище
`max_gift_price` з активної акції типу `gift_threshold`.

### Дефолти

При першому запуску таблиця `promotions` наповнюється двома акціями, які працювали до появи
адмінки: `order_10_percent` (−10% від 500 ₴) і `gift_3_toys` (подарунок за 3 брелки).

Банк ідей для нових акцій — у файлі `ПРОМО-ІДЕЇ.md`. Частина з них є готовими шаблонами
у формі створення акції.

## 12) Користувачі бота

Вкладка **👥 Користувачі** в адмінці показує всіх, хто хоч раз запускав бота.

### Що видно по кожному

| Колонка | Що означає |
|---|---|
| Користувач | Ім'я, `@username` (клікабельний), Telegram ID, позначка «заблокував бота» |
| 🚀 Запусків | Скільки разів надіслав `/start` |
| Останній запуск | Дата останнього `/start` |
| 💬 Дій | Будь-які взаємодії з ботом: повідомлення, кнопки, відкриття каталогу |
| 📦 Замовлень | Кількість замовлень усіх статусів |
| 💰 Сума | Сума **підтверджених** замовлень |
| Перший запуск | `joined_at` — коли користувач уперше потрапив у базу |
| Дії | «Написати» (t.me/username) або «Копіювати ID», якщо username немає |

Є пошук (ім'я / `@username` / ID), фільтр за статусом блокування, сортування по кожній
колонці та пагінація по 50 записів.

### Як рахуються лічильники

- `users.start_count` / `users.last_start_at` — інкремент у хендлері `/start` (`services.users.record_start`).
  Через `@command_cooldown` спам `/start` поспіль не накручує лічильник.
- `users.activity_count` / `users.last_seen_at` — інкремент у `auto_register_user`
  (`services.users.record_activity`), тобто на будь-якому апдейті від користувача.

### Історичні дані

Лічильників не існувало до цієї міграції. Під час першого `init_db` після оновлення всім
наявним користувачам одноразово проставляється `start_count = 1` і `last_start_at = joined_at` —
вони вже колись запускали бота. Точні цифри збираються з моменту деплою.

### API

```
GET /api/admin/users?search=&blocked=all|active|only&sort=starts&order=desc&limit=50&offset=0
```

`sort`: `starts`, `activity`, `orders`, `spent`, `joined`, `last_start`, `last_seen`, `name`.
Відповідь: `{"users": [...], "total": N, "limit": N, "offset": N}`.


**Статус:** актуалізовано під поточний код.
