## 🏗️ Архітектура

### Фронтенд (index.html)
- Чистий HTML/CSS/JS без фреймворків
- Шрифт: Nunito
- Telegram WebApp SDK підключений
- Товари завантажуються через `fetch()` з `products.json` і `custom_products.json` (✅ Етап 1)
- Адаптивна темна/світла тема через CSS змінні (✅ Етап 0)
- Bottom nav + таби категорій (✅ Етап 2)
- Кошик в localStorage + анімація видалення (✅ Етапи 4–5)
- Замовлення надсилається через HTTP POST на `/order` ендпоінт бота

### Бот (bot.py)
- python-telegram-bot (async)
- aiohttp HTTP сервер на порту 8080 (паралельно з polling)
- SQLite база даних (файл `users.db`)
- Два шляхи відкриття міні-апп:
  1. Main App кнопка (біля назви бота в списку чатів) → `handle_order` (HTTP)
  2. Кнопка після `/start` → `web_app_data` (WebApp data)
  - **Обидва обробники залишаються, нічого не видаляти**

## 📦 Структура products.json (нова)

```json
{
  "id": 1,
  "cat": "toy",
  "emoji": "🐉",
  "photos": ["url1", "url2"],
  "name": "Fidget-спіраль",
  "mat": "PLA · один або два кольори",
  "price": 300,
  "oldPrice": 400,       // якщо є — товар автоматично потрапляє в "Акції"

  "gift": false          // true = може бути подарунком (ціна має бути ≤ 100 грн)
```

> Акція визначається наявністю `oldPrice` — окреме поле `sale` не потрібне.
> `gift: true` — тільки в `products.json`, не в `custom_products.json`.

## 🛒 Логіка кошика

- Зберігається в **localStorage**
- Читається один раз при старті, зберігається в JS змінну, пишеться при змінах
- Кожен товар в кошику: `{ id, name, price, quantity, fromCustom: bool }`
- Лічильник на іконці кошика оновлюється точково (не перемальовує грид)

### Анімація видалення (quantity → 0):
1. Блок товару слайдом іде вліво
2. На його місці з'являється плашка "Повернути [назва товару]"
3. Прогрес-бар зменшується 3 секунди (видно таймер)
4. Клік по ВСЬОМУ блоку (не тільки текст) — повертає товар
5. Через 3 секунди — товар остаточно видалений, блок зникає

---

## 🎁 Логіка подарунку

- Активується коли в кошику **3+ унікальні позиції** (рядки, не кількість штук)
- Подарунок тільки з **`products.json`** (не з custom_products.json)
- Умова: `gift: true` і `price ≤ 100` грн
- Система обирає випадковий подарунок автоматично
- В кошику з'являється блок:
  ```
  🎁 Подарунок від нас!
  [назва подарунку] — безкоштовно
  [Обрати інший ↻]
  ```
- Кнопка "Обрати інший" → модалка зі списком всіх доступних подарунків на вибір
- В повідомленні боту: окремий рядок `🎁 Подарунок: [назва]`

## 🌙 Адаптивна тема (Етап 0 — першочергово)

Міні-апп має підтримувати світлу і темну тему залежно від теми Telegram у користувача.

### Принцип:
- Використовувати CSS змінні (`--bg`, `--card-bg`, `--text`, тощо)
- При ініціалізації читати `Telegram.WebApp.colorScheme` (`'light'` або `'dark'`)
- Слухати подію `Telegram.WebApp.onEvent('themeChanged', ...)` для динамічної зміни
- Застосовувати клас `dark` на `<html>` або `<body>` і перевизначати змінні

### Охоплює ВСЕ:
- Хедер, фон, картки товарів
- Модальне вікно товару (всі блоки всередині)
- Bottom navigation
- Таби категорій
- Сторінка кошика (всі елементи)
- Блок подарунку
- Плашка "Повернути товар" з таймером
- Скелетон при завантаженні
- Success screen
- Lightbox (перегляд фото)
- Поля вводу (textarea)
- Всі кнопки і бейджі

### Кольори для темної теми (орієнтовні):
```css
--bg: #1a1a1a
--card-bg: #2a2a2a
--text: #ffffff
--muted: #aaaaaa
--border: rgba(255,255,255,0.08)
```

## ⚡ Швидкодія (Етап 11 — фінальний прохід)

- `disableVerticalSwipes()` — при старті (щоб свайп вниз не закривав апп)
- Скелетон при завантаженні JSON (сірі плейсхолдери карток)
- Всі анімації тільки через `transform` і `opacity` (GPU, без layout reflow)
- `decoding="async"` на всіх `<img>`
- Перше фото в модалці `loading="eager"`, решта `loading="lazy"`
- Точкове оновлення DOM (лічильник, сума — без перемальовування гриду)
